# 苏格拉底 × 破壳

## 何时使用

用户打开任意网页（校园通知、新闻、知乎、公众号镜像页），希望：

- 不被 AI 总结糊弄过去
- 发现自己信息茧房与认知盲区
- 得到可截图、可发给朋友讨论的具体问题

**不要**在用户提供空页面时使用——必须先有内容或粘贴文本。

## 变量

| 变量名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| 输入模式 | 选项 | @当前页面 | `@当前页面` 或 `粘贴内容` |
| 问题强度 | 选项 | 标准 | `温和` / `标准` / `挑战` |
| 关注方向 | 选项 | 机会嗅探 | `专业相关` / `机会嗅探` / `创业竞赛` / `随机破壳` |

## 执行前

1. 若 **输入模式 = @当前页面**：读取用户 @ 的 tab 正文（标题 + 可见正文 + 列表项）。若读取失败，提示用户切换到「粘贴内容」并粘贴全文，**不要**编造页面内容。
2. 若 **输入模式 = 粘贴内容**：使用用户粘贴的文本。
3. 若正文少于 80 字，提示「内容太短，请打开详情页或粘贴完整正文」。

## Step 1 — 具体提取（禁止泛泛而谈）

从正文中提取，写入内部笔记（不必全部展示给用户）：

- **核心断言**：页面在说什么具体结论？（一句话，含可验证事实）
- **具名实体**：人名、机构、日期、数字、地点（至少 3 项，不足则标注「文中未给出」）
- **隐含假设**：作者默认读者已经知道什么？
- **未回答的问题**：文中没提但读者该问什么？

若无法提取具名实体，停止并提示用户打开详情页。

## Step 2 — 茧房诊断（2–3 句）

结合 **关注方向**，说明：

- 这条信息会强化你哪类信息饮食？
- 你可能因此**错过**什么类型的机会或视角？

禁止空话（「你可能有偏见」），必须引用 Step 1 的具体实体。

## Step 3 — 三个苏格拉底式问题

根据 **问题强度** 生成恰好 3 个问题，格式：

```
Q1（澄清）：……
Q2（挑战假设）：……
Q3（行动/破壳）：……
```

规则：

- 每个问题必须包含至少 1 个来自正文的**具体名词或数字**
- Q3 必须与 **关注方向** 相关，并指向一个可执行的 micro-action
- **禁止**输出答案或建议阅读清单

## Step 4 — 破壳推荐

从正文的**对立面或相邻领域**推荐 1 条「破壳」阅读/行动方向：

- 一句话说明「为什么这条和你的日常信息流不同」
- 给一个可搜索的关键词或校内场景（如「去团委通知页搜创新创业」）

## Step 5 — 输出格式（严格）

```
🫧 茧房诊断
[Step 2 内容]

❓ 三个问题
[Step 3 内容]

🌱 破壳一下
[Step 4 内容]

📤 发给朋友的版本（复制即可）
「我刚看到 [核心断言里的一个实体]，但有个问题没想通：[Q2 改写为口语一问，<=40字]」
```

## 局限说明（写入妙招描述）

- 需要页面有足够正文；列表页请点开详情
- 不替代事实核查；问题是思考起点，不是结论
- 与破壳小程序「破壳推荐」模块理念一致，可配合 `prompt-poke-feed` 导入行动
