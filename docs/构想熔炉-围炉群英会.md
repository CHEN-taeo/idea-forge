# 构想熔炉 · 围炉群英会（Roundtable Mode）

> **状态**：已实现 MVP · Idea Forge 单人 AI 模式  
> **入口**：首页 → **围炉群英会**（`LandingPage` → `App.tsx` → `RoundtableMode`）  
> **与多人「围炉」区别**：多人围炉 = Socket.IO 房间；围炉群英会 = 一人 + AI 虚拟嘉宾，走 REST，无需房间码。

---

## 1. 产品定位

| 模式 | 参与者 | 目标 | 技术 |
|------|--------|------|------|
| **围炉（多人）** | 真人 + 投屏 | 结构化头脑风暴 → 认领 | Socket.IO + SQLite |
| **独思（Solo）** | 仅自己 + AI 教练 | 15 分钟想明白 → 认领 | REST |
| **围炉群英会** | 自己 + 1–3 位 AI 嘉宾 | 围炉夜话、多角度对谈 → 复盘 → 认领 | REST |

**一句话**：像游戏一样选大佬入席，围炉聊透一个问题，聊完收束并领一件事。

与 [`构想熔炉-关系模式-spec.md`](./构想熔炉-关系模式-spec.md) 的关系：关系模式面向**真人多人**；群英会已落地其中部分能力（话术模板、心理安全 3 题、承诺仪式），作为**单人 AI 版**关系护栏试验场。

---

## 2. 用户流程

```
setup（定话题 + 选嘉宾）
  → table（圆桌对谈）
  → debrief（心理安全 3 题）
  → wrap（AI 收束 + 认领行动）
  → done（完成）
```

### 2.1 会前 · setup

- 步骤 1：名字 + 话题  
- 步骤 2：选 **1–3 位**嘉宾（快捷组合：创业三角 / 思辨之夜 / 悟道组合）  
- **入席预览**：迷你圆桌 + SVG 立绘  

### 2.2 会中 · table

- 环形圆桌 UI：中央围炉 🔥，嘉宾沿弧入座，用户在正下方  
- 用户发言 → **智能调度** 1–3 位嘉宾顺序接话  
- **`@嘉宾名`** 或 **`@personaId`**：只指定该嘉宾回应  
- **话术模板**（输入框上方）：复述 / 是的而且 / 我不同意 / 回到核心 / Steel-man  
- **开场白快捷按钮**（空状态时）  
- **让他们再聊一轮**：无用户新发言，嘉宾继续互相对话  
- **☯ 结束围炉**（至少 2 条消息后）→ 进入复盘  

### 2.3 会后 · debrief → wrap → done

**复盘（3 题李克特 1–5）**

1. 这次讨论里，我敢表达不同意见  
2. 我感到被倾听  
3. 我不担心因说错而被否定  
4. （可选）关于沟通本身，我学到…  

**收束（AI 四段总结）**

- 共识 / 分歧 / 还缺什么 / 建议下一步  
- **🤖 AI 写行动**：复用 `/api/ai/smart-action`（与独思相同）  
- **✍️ 确认认领**：14 天内具体行动  

**完成页**：展示承诺 +「再来一场围炉」  

**导出 Markdown**：对话 + 收束 + 复盘分数 + 承诺（可在 wrap 或 table 阶段部分导出）

## 4. 技术架构

### 4.1 文件地图

| 路径 | 职责 |
|------|------|
| `src/app/components/RoundtableMode.tsx` | 全流程 UI（setup / table / debrief / wrap / done） |
| `src/app/components/PersonaPortrait.tsx` | SVG 立绘 + 用户头像 |
| `src/app/data/personas.ts` | 嘉宾展示数据 |
| `src/app/lib/roundtableLayout.ts` | 1/2/3 人环形座位坐标 |
| `src/app/lib/aiClient.ts` | REST 客户端 |
| `src/app/App.tsx` | `roundtable` 路由开关 |
| `src/app/components/LandingPage.tsx` | 首页入口 |
| `src/styles/theme.css` | `rt-*` 围炉场景样式、`page-card` |
| `ai.js` | `personaReply`, `pickPersonaResponders`, `summarizeRoundtable` |
| `server.js` | REST 路由 |

### 4.2 数据流

```
RoundtableMode.tsx
  → aiClient.ts (fetch)
  → server.js (Express)
  → ai.js (DeepSeek 或 template fallback)
```

- **无 Socket.IO**，与多人游戏隔离  
- **无 SQLite 持久化**（刷新丢失；导出 Markdown 为唯一留存）  
- 依赖 `VITE_SERVER_URL` 指向后端（默认 dev：`http://localhost:3001`）

### 4.3 智能调度逻辑

1. 用户 `@指定` → 仅该 `personaId` 发言  
2. 否则 `pickPersonaResponders()`：  
   - **有 API Key**：AI 返回 JSON `{"order":["id1","id2"]}`  
   - **无 Key**：按历史发言次数排序，用户发言后最多 2 人，「再聊一轮」全员  
3. 每位嘉宾 `personaReply(..., lastSpeaker)`：prompt 要求点名回应上一位

## 5. REST API

Base：`PORT`（默认 `3001`）。均需 `Content-Type: application/json`。

### `GET /api/ai/status`

返回 `{ enabled, model, mode: 'ai' | 'template' }`。

### `POST /api/ai/persona/dispatch`

决定本轮发言顺序。

**Body**

```json
{
  "personaIds": ["musk", "socrates"],
  "topic": "该不该辞职创业",
  "history": [{ "speaker": "小陈", "text": "..." }],
  "userMessage": "你们怎么看",
  "userName": "小陈",
  "targetPersonaId": ""
}
```

**Response**：`{ "order": ["socrates", "musk"], "mode": "ai" }`

### `POST /api/ai/persona/reply`

单嘉宾一条回应。

**Body**

```json
{
  "personaId": "socrates",
  "topic": "...",
  "history": [...],
  "userMessage": "...",
  "userName": "小陈",
  "lastSpeaker": "马斯克"
}
```

**Response**：`{ "reply": "...", "mode": "ai" }`

### `POST /api/ai/persona/summarize`

围炉收束总结。

**Body**

```json
{
  "topic": "...",
  "history": [...],
  "personaIds": ["musk", "marx"]
}
```

**Response**

```json
{
  "consensus": "...",
  "disagreement": "...",
  "gap": "...",
  "nextStep": "...",
  "raw": "...",
  "mode": "ai"
}
```

### `POST /api/ai/smart-action`（复用独思）

收束页「AI 写行动」。Body：`{ ideaText, problem, playerName }`。

## 6. 环境变量

与 Idea Forge 根目录 `.env` 共用：

| 变量 | 用途 |
|------|------|
| `AI_API_KEY` | DeepSeek（或兼容 OpenAI API）；空则全模式 template 兜底 |
| `AI_API_URL` | 默认 `https://api.deepseek.com/v1` |
| `AI_MODEL` | 默认 `deepseek-chat` |
| `VITE_SERVER_URL` | 前端请求后端，如 `http://localhost:3001` |
| `PORT` | 后端端口，默认 `3001` |

## 9. 与独思（SoloMode）对比

| | 独思 | 围炉群英会 |
|--|------|------------|
| 结构 | 角度 → 写想法 → 筛选 → 认领 | 自由对谈 → 复盘 → 收束 → 认领 |
| AI 角色 | 单一教练 | 多 persona 角色扮演 |
| 多人感 | 无 | 圆桌 + 立绘 + 互怼 |
| 承诺 | ✅ | ✅（复用 smart-action） |

可未来打通：围炉收束 → 一键导入独思「候选想法」列表。

## 10. 已知限制 & 后续方向

**当前限制**

- 嘉宾回复**串行**请求，3 人时 latency 叠加  
- 无 session 持久化（刷新清空）  
- 立绘为抽象 SVG，非写实  
- 名人 persona 仅供思辨练习，非真实观点  

**建议迭代**

- [ ] 并行生成 + 前端 stagger 展示（降延迟）  
- [ ] `localStorage` / SQLite 保存未完成围炉  
- [ ] 自定义嘉宾（用户填性格 prompt）  
- [ ] 与 Obsidian / `docs/大学讨论-*` 方法库联动推荐嘉宾  
- [ ] 与多人关系模式 spec 共享 debrief 组件  
- [ ] `React.lazy` 拆分 RoundtableMode 减 bundle
